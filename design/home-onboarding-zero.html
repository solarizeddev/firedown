Firedown — zero-state onboarding home card

The first-install home (left) shows the live stats 3-up reading 0 / 0 / 0 — a dead placeholder that teaches a brand-new user nothing about what the app does. These sketches swap that single card for a one-time onboarding card while every count is still zero, then morph back into the existing stats card the moment the first tracker is blocked or the first file is saved. Styled to the real light (cream) home from the screenshot. Per the architecture there is deliberately no "paste a link" box — Firedown captures from live pages you browse, so the call-to-action just focuses the address bar (the same thing tapping it already does), and the steps teach the browse-to-capture mechanic honestly.

C · jump-start

Shortest path to first capture

A brand-new user has no history, so seed a few well-known media sites as launch tiles. The card explains the loop in one line; the tiles get them onto a real page (where capture happens) in one tap.

How it binds to the real app. Show the onboarding card in fragment_home.xml in place of home_stats_card only on a true fresh install — all three live figures still zero (trackers == 0 and saved == 0 and Safe Folder == 0). In HomeFragment the three existing observers already feed those numbers; gate a ViewSwitcher (onboarding ↔ stats) on the AND of them, flipping to the stats card the first time any becomes non-zero (a tracker is blocked within seconds of the first page, so the card naturally retires on its own). The Start browsing / Search CTA calls the same focus path the omnibox tap uses (mGeckoToolbar.getAutoCompleteEditText().requestFocus() + show keyboard) — it opens nothing and promises nothing the address bar can't already do, honouring the "no paste-a-link flow" invariant. The "Jump in" tiles (C) reuse the existing openUri(...) entry. New copy lives as home_onboard_* strings, translated across the same 16 locales as the other home strings.
