Firedown · design sketch · the shield sheet with two ad blockers

One number on the shield sheet

On the device the sheet showed 27 blocked on this page, then uBlock Origin 31 and Ghostery 22. The three numbers measure different things. 27 is Firedown's own count: requests a blocker cancelled, each counted once. 31 is uBlock's badge, which probably also counts requests it redirects to a harmless stand-in, which never reach Firedown's counter. 22 is Ghostery's badge, which counts trackers, not requests. Side by side they read like a sum that doesn't add up.

Dashed amber marks what reads wrong today. Dashed coral marks the change. Numbers are the ones from the screenshot.

Today, A and B

Why A

  • One measurement per sheet. The shield in the address bar, this row and the "Blocked on this page" list all show the same count. A second kind of number only invites the question "why 31 when it says 27?", and the sheet has no room to answer it.
  • The badge isn't lost. A tap on the row opens the add-on's popup, which shows its own count with its own label.
  • Rows read alike. Every blocker row has a name and a status line, so the rows are the same height and the names have the width the number used to take.
  • No attribution is possible. Firedown sees that a request was cancelled, not which add-on cancelled it, so the total can't be split per blocker in either design.
  • What changes in code: the row drops its count view, gains a status line for every blocker, the name goes to one line with an ellipsis, and the total row's text names requests. No new strings beyond "On".
