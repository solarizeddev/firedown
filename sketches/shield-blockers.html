Firedown · design sketch · official uBlock Origin

Blockers behind the shield

Firedown installs the official uBlock Origin (Mozilla-signed, bundled in the APK, updated from addons.mozilla.org) instead of its custom copy. The shield at the start of the address bar becomes the door to it: the security sheet keeps its count and blocked hosts, and the old Block ads and trackers switch is replaced by a uBlock Origin row that opens uBlock's own popup, where its per-site switch lives. The refresh button stays: it is also Stop.

Dashed outlines mark what is new or changed. Numbers are examples.

With uBlock Origin (the default)

The shield mirrors the blocker's state

uBlock Origin titles its toolbar button for each tab: uBlock Origin (23) while it filters there, uBlock Origin (off) once the user turns it off for that site (its own code, vapi-background.js, setTitle). Firedown already receives that title per tab, so the shield takes the same state with no bridge. Site exceptions from the custom copy are not carried over; the user sets them again in uBlock's popup.

  • The rule: protection is on for a tab when at least one blocker is enabled (and allowed in private tabs, for a private tab) and none of the enabled ones says off for this tab. Only uBlock Origin says per-site off through its title; another blocker counts as on while it is enabled.
  • A tab uBlock has not titled yet (first frame of a page) shows its default title, read as on.
  • The secure / not-secure half of the shield is unchanged.

When the user installs another blocker

Every blocker on the page gets its own row, uBlock Origin first. The total is counted once per request, so two blockers cancelling the same request count it once. Each add-on's own number is what that add-on reports (Privacy Badger counts trackers, not requests), so the rows don't add up to the total and the sheet never sums them.

Which add-ons get a row

A row is for an add-on that blocks requests on every site: it holds webRequestBlocking or declarativeNetRequest with access to all sites, and it has a toolbar button. That is read from the add-on's own permissions, so no list of blocker names to keep. The catch is that a few non-blockers hold the same permissions (an add-on that rewrites links or changes a header), so the add-on's page in Settings gets a Show behind the shield switch to correct either way.
